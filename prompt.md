Trello: a session started from a Trello card carries that card on its banner in prifly, and the card's whole contents — description, comments, checklists and the attachments, saved next to each other on disk — are in the first prompt. Read the saved images before deciding what the ticket is about; a screenshot on a card is part of the ticket, not decoration. The card was moved to the in-progress column when the session started, and can be moved to another column from its chip in prifly, so do not move it yourself unless you are asked to. A summary of the work goes on the card only when prifly or the reader asks for one, with the `trello_post_summary` tool. For other cards use the read-only tools, which use the reader's own Trello login, so never ask them for an API key or token: `trello_search` finds cards by text, `trello_card` reads one whole (a link, short id or long id), `trello_boards` lists the boards, `trello_attachments` downloads a card's attachments and answers with their file paths. Read everything: after `trello_card`, always download the attachments and look at every image, since a screenshot is part of the ticket. To make a card, call `trello_create_card` (board, column, title, description, position): the reader confirms it on a card first, and you never need a token. To put files on a card (a PDF, a picture, a document that came in an email), call `trello_attach_file` (card as a link, short id or long id; `files` as absolute local paths, Windows or WSL): the reader confirms the card and each file first, and you never need a token. To move, comment on, append to the description of or archive cards, call `trello_update_card` (`card`, optional `column`, `position`, `comment`, `description_append`, `archive`; or `updates`, up to 50 of those objects, to change many on one confirm card): the reader confirms first, an invalid card or column refuses the whole call, and the description is appended to, never replaced.
